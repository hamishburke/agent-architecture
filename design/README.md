# design

Designs from **11 November 2026** onward.

The designs written before that date stay where they were — `design/implementations/` in the log
repository — because every board record that ever pointed at one points there, and moving them
would break those links while gaining nothing a reader can use. History lives with the log; new
designs live here, where the architecture is.

The convention, unchanged from the log repository:

- One change, one reason, in the commit message: what broke, what it now does, what would show
  it is wrong.
- The falsifier is part of the document, not a footnote. If nobody can say what the numbers
  would look like when the claim fails, the document is a proposal.
- Say plainly what was **not** implemented. A design that lists only what it does reads as
  complete and is usually not.
- Disagreement is a file, not a message: write the measurement and let it settle.
